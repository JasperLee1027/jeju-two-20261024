# 兩人共用花費

網站維持 GitHub Pages 靜態部署。共用資料放在擁有者的 Google Apps Script Script Properties，與私人 Doc 同步共用原部署，但使用獨立房間及存取金鑰。瀏覽器只取得共用花費金鑰，不能讀取或修改 Doc。

## 使用方式

1. 在有完整自訂花費的裝置，開擁有者提供的私人共用連結。網站立即清除網址中的連線片段，並保留加入前的本機備份。
2. 空白共用資料須按「用這台的花費建立共用資料」，不會自動用網站預設值覆蓋。
3. 按「複製共用連結」，私下傳給旅伴或自己的其他裝置。每台首次開啟後選「開啟共用花費・保留這台備份」；若另一台也有獨有內容，可改選合併。
4. 之後直接開平常的網站即可。修改後約1秒啟動同步；另一台在花費頁約15秒核對一次，其他分頁約45秒，也可按「立即同步」。背景分頁回到前景時再核對。

只同步花費選項、匯率、自訂項目及金額；想去、待辦、Doc手動內容仍使用原來方式。已付款訂單的正式內容由網站資料決定，花費比較選項不會改寫訂單。

離線時保留這台修改，連線恢復後合併；不同欄位可合併，同一欄同時改成不同內容時會列出兩份值讓使用者選擇。輸入金額期間不會立即套用旅伴的修改。只有讀回伺服器的寫入確認才顯示已同步。

「下載花費備份」包含目前資料與最多10份本機歷史備份，不含連線金鑰。「停止這台共用」保留這台資料，不會刪除其他裝置或伺服器的資料。此版本提供下載備份，沒有自動匯入備份功能。

私人共用連結持有人可讀寫該份花費，請只傳給旅伴；不要放入公開網站、Issue、截圖或公開文件。清除瀏覽資料後需要重新加入。第一次加入後請關閉該裝置同網站其他舊分頁，避免舊頁面覆寫本機狀態。

## 維護與部署

`Code.gs.txt` 是完整的 Doc＋花費服務程式。更新原本 Apps Script 專案後，使用「部署 → 管理部署作業 → 編輯 → 新版本 → 部署」，保留原 `/exec` 網址、原 Doc 綁定與私密設定。不必重跑 `setup()`。來源檔沒有實際文件 ID、部署網址或金鑰。

`costSetup`、`costProbeCreate`、`costProbeRemove` 只有持有私人 Doc 管理金鑰的伺服器端工具可呼叫。`costSetup` 取得穩定正式房間，但不填入花費；瀏覽器透過 `costRead`、`costWrite` 和獨立花費金鑰讀寫。測試只能用 probe 房間，完成後移除。正式房間不接受 probe 清除動作。

`cost-sync-model.js` 定義共享資料與三方合併；`cost-sync-client.js` 管理離線、重試、版本衝突及備份；`cost-sync.js` 負責介面與傳輸。讀取 JSONP 放在不能存取主網站資料的 sandbox iframe，寫入使用簡單 POST，再讀回確認寫入 ID，避免將不透明回應當成功。後端以鎖與版本號防止互相覆蓋，分段保存並保留上一版。

更改模型或 `CostsService.gs` 時須同步重建完整 `Code.gs.txt`，再驗證合併服務保留 Doc 功能。部署網址、金鑰與私人連結僅存在擁有者私有設定及各裝置本機儲存，不可提交到公開儲存庫。
